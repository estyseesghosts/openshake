# Architecture

## Branches and data flow

```text
anomalyco/opencode@vX (upstream ref)
        │ git archive of packages/{tui,latex,merman}
        ▼
vendor-source  ── pristine snapshots, never fork changes
        │ rebase
        ▼
tui-fork       ── snapshot + OpenShake commits (the only place to edit vendored code)
        │ git subtree merge --prefix=vendor ... --squash
        ▼
main           ── first-party src/ + assembled vendor/ ; the runnable branch
```

Always make vendored changes on `tui-fork`; `main` receives them only through the subtree merge.
`vendor-source` is regenerated by `bun run vendor:sync <ref>` and must stay byte-identical to the
upstream archive.

## Runtime boundaries

`src/main.tsx` is the composition root. It resolves the backend, installs the Bun alias plugin for
the two private renderer packages, then calls `vendor/tui/src/index.tsx`'s `run()` with a config
service, event stream, and a log sink. `src/backend.ts` parses CLI options and decides between the
local service and a remote endpoint; all environment-variable and URL validation happens there.

The vendored TUI owns the terminal. First-party log output is buffered and emitted after shutdown
so it cannot paint over a rendered frame; `OPEN_SHAKE_DEBUG=1` opts into debug/info output.

## Fork modules (all under `vendor/tui/src/`)

### Transcript presentation — `routes/session/`

- `grouping/session.ts` — mode-specific `partPath()` policies. `low` keeps its original activity
  summary, `high` keeps exploration/reasoning/instruction grouping, and `medium` adds
  `medium-activity` / `medium-edits` paths. Failed tools and interactive tools stay standalone.
- `rows.ts` and `rows-index.ts` — pure row projection plus an O(1) index of materialized parts and
  reasoning-group owners. Streaming deltas for an already visible part early-exit before touching
  the Solid store.
- `group-view.tsx` + `medium-activity-summary.ts` — semantic group headers, a bounded live line for
  the newest genuinely running child, and transparent singleton groups so a lone edit keeps its
  real `PatchDiff`. apply_patch headers count changed files, not tool calls.
- `logo.ts` and `component/logo.tsx` — the `shake` launch wordmark. Rows are single text nodes so
  the four-wide pixel grid stays aligned; `util/presentation.ts` reuses it for the exit epilogue.

### Client data layer — `context/`

`data.tsx` imports `createData` from `fork-data.ts`. That module re-exports the published
`@opencode/client/solid` surface but replaces `createData` with the local `client-data.ts`, which
is a fork of upstream `packages/client/src/solid/data.ts` (version 2.4.1) with:

- `stream-coalescer.ts` — per-part accumulators, last-write-wins progress, synchronous flush on
  lifecycle events and disposal. The scheduler is injected from `data.tsx`, which publishes at most
  once per rendered frame via the renderer's frame event.
- `message-window.ts` — page-aware, byte-budgeted residency with cursors, whole-page eviction, and
  pinned pending/streaming messages.
- `session-pages.ts` — iterative cursor traversal for child pages (no recursion or cursor cycles).
- `idle-markers.ts` — idle-marker presence tracked as metadata instead of rescanning history.
- `session-aggregates.ts` — root/family counters reconciled from reactive member state, so drawing
  many tabs does not walk every family.
- `session-tabs-thermal.ts` — tab warmth policy and bounded background hydration.

Other forks in `util/`: `media.ts` (byte-accounted LRU), `diff-highlight.ts` (linear prefix offsets
and a highlight budget), `startup-timing.ts` (startup marks), and `load-benchmark.ts` (deterministic
fixtures and the opt-in benchmark).

## Tests

Fork tests live beside upstream tests under `vendor/tui/test/` and are not part of `bun run verify`.
Pure tests need the OpenTUI Solid preload; rendered tests additionally need the TUI test preload.
See the README for exact commands.
